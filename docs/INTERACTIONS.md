# Жесты и прокрутка

- Используем системную прокрутку браузера с инерцией. Не перехватываем вертикальные свайпы и обычное колесо мыши.
- Свайп по карточке, кнопке или полю не выполняет действие. Действие происходит при коротком нажатии или с клавиатуры.
- Горизонтальные управляющие жесты захватываем только после определения направления и небольшого порога движения; вертикальный жест передаём странице.
- Слайдер бронирования: движение вправо, в том числе диагональное, с отпусканием подтверждает. Допускаем вертикальный дрейф до трёх горизонтальных расстояний. Явно вертикальный жест прокручивает страницу, отмена жеста сбрасывает ползунок. Для завершения достаточно около 60% длины дорожки. Обработка касаний локальна для слайдера; страницу не перехватываем.
- 3D-модель: на телефоне горизонтальный жест поворачивает модель, вертикальный прокручивает страницу. Обычное колесо прокручивает страницу; Ctrl/Command + колесо и отдельные кнопки меняют масштаб модели.
- Галерея переключает фото только при преимущественно горизонтальном свайпе одним пальцем. Вертикальный жест и масштабирование не переключают фото.
- Широкие таблицы поддерживают горизонтальную прокрутку и сохраняют вертикальную прокрутку страницы.
- Диалоги блокируют прокрутку страницы под ними; их содержимое и всплывающие списки прокручиваются внутри без передачи жеста фону на границе.
- Поля на мобильном имеют шрифт не менее 16 px, чтобы избежать автоматического приближения при фокусе.
- Учитываем фиксированную шапку при переходах и фокусе. Масштабирование браузера остаётся доступным.
- Звук действия воспроизводится после активации, а не при первом касании во время свайпа.
- На мобильном прокручивается сам документ, а не внутреннее окно: браузер может скрывать и возвращать свои панели при свайпе. CSS отсечение имеет запас 20 px внутри непрозрачной шапки, не под её нижним краем (44 px). Его синхронизирует root scroll timeline; JavaScript обновляет только длину страницы при изменении геометрии. Непрозрачная шапка перекрывает запас под этой границей, чтобы задержка отрисовки не давала полосу ниже неё. Неподвижный слой узора ниже 27 px заполняет фон под скруглениями при задержке; основной прокручиваемый фон сохранён, включая область под нижней панелью браузера. Шапка закреплена через sticky в дереве отрисовки документа, с непрозрачной подложкой над её фигурной частью; у её SVG нет фильтра размытой тени. Прямоугольная подложка заканчивается до нижних скруглений.
- Область над шапкой сплошная белая в светлой теме и чёрная в тёмной, на всех маршрутах. Нижнего отсечения карточек нет.
- При просмотре фото верхняя и нижняя подложки и цвет интерфейса браузера переключаются на тёмный; закрытие восстанавливает выбранную тему.

- Телефоны до 700 px используют мобильную компоновку. Планшеты до 1100 px в портретной ориентации используют мобильную компоновку, в горизонтальной — desktop с более узкой правой колонкой. CSS и JavaScript используют одно условие; поворот обновляет геометрию без сброса страницы.
- В Яндекс Браузере и обычном Safari дополнительное отсечение отключено, чтобы не обрезать карточки под шапкой. Для Telegram сохраняется подтверждённая защита верхнего края; его Safari-подобный User-Agent различается по внедрённому native bridge (contentInterface + performAction).
- Фон нижней области рисуется на корневом холсте браузера; дополнительного отступа после футера нет. Верхняя половина холста остаётся сплошной под шапкой. Логотип на телефоне не выделяется и не перетаскивается; focus-обводки объектов отключены по пожеланию владельца.

- Фон BODY совпадает с базовым цветом узора, поскольку WebKit использует его для underPageBackgroundColor. Узор ниже документа продолжен через border-image-outset (ink overflow) без увеличения scrollHeight и без подъёма футера. Открытая фотогалерея сохраняет отдельную тёмную подложку.
