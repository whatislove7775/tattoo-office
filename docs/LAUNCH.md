# Подготовка к боевому запуску

Версия от 6 октября 2026 года — проверенный локальный тестовый стенд. Действующий сайт не опубликован заново.

## Заполняется владельцем в админке

Адрес, контакты, ИП/ООО и ИНН, часы работы, тарифы резидентов/гостей, услуги, остатки, размер предоплаты, срок ранней отмены, правило поздней отмены, срок напоминания, правила и их версия, политика, отдельное согласие, оферта. Имена и авторство фотографий/работ также надо подтвердить и заполнить. Стоимости в исходном seed — тестовые.

## Требуются доступы

- PostgreSQL и сервер в РФ, HTTPS-домен, резервные копии и восстановление.
- CloudPayments Public ID / API Secret и кабинет песочницы конкретного мерчанта. Общих чужих ключей в коде нет.
- CloudKassir Public ID / API Secret, зарегистрированная касса, ИНН, система налогообложения и ставки НДС. Уточнить предмет расчёта аренды/услуги с бухгалтером.
- Telegram Client ID/Secret из BotFather; разрешённый callback `https://DOMAIN/api/auth/telegram/callback`; Bot Token для уведомлений.
- Google service account JSON; отдельный Calendar ID каждого рабочего места; права сервисного аккаунта на эти календари.
- Email API: HTTPS endpoint, token; контракт POST `{to, subject, text}` с поддержкой Idempotency-Key. Это адаптер для выбранного сервиса, а не настройка уже оплаченного провайдера.
- Код/контракт текущего Telegram-бота для фактического переключения на общий API.

## Обязательные доработки и приёмка перед реальными платежами

1. Проверить на стенде мерчанта CloudPayments Check/Pay/Fail, точную сумму, валюту, AccountId, подпись и повторную доставку. Отдельно обработать платёж, пришедший после освобождения резерва: деньги нельзя потерять; нужен процесс сверки/возврата.
2. Реализовать и проверить Refund и кассовые документы отмены/возврата, перенос аванса на внутренний баланс, оплату новой записи этим авансом, полностью покрытый авансом итоговый счёт. Сейчас реализованы базовые документы внешней предоплаты и финального платежа; полная фискальная цепочка внутреннего баланса ещё не сертифицирована тестами.
3. Добавить проверку Receipt webhook и сверку статуса чека. API-ответ «поставлен в очередь» не равен успешной фискализации. Повтор сомнительного чека автоматически не отправляется: очередь переходит в `review`, поскольку идемпотентность провайдера ограничена по времени.
4. Убедиться, что реквизиты покупателя фиксируются на платеже/чеке, налоговые настройки сохраняются на каждой операции и не меняются задним числом. В этой версии цена и правила уже фиксируются на брони; фискальные настройки требуют следующей миграции перед live.
5. Подключить проверку email, восстановление доступа и согласовать хранение/удаление данных, сроки хранения логов, модель доступа сотрудников, резервное копирование. Не принимать реальные персональные данные в публичном тестовом режиме.
6. Прогнать PostgreSQL через Docker с конкурирующими клиентами и перезапуском worker. В текущей среде Docker отсутствовал; проверено на PGlite с PostgreSQL-семантикой, а не на отдельном контейнере.
7. Подключить внешний Email/TG/Calendar и проверить доставку. В тестовом режиме внешних отправок нет. Уведомления сейчас есть в кабинете, Web Push/service worker не реализован.
8. Снять программную блокировку `mode=live` только после прохождения пунктов выше; заменить её явным списком проверенных условий. Кнопка переключения без этих проверок намеренно отсутствует.

## Правовые основания и границы

- [152-ФЗ, официальный текст на сайте Минтруда](https://mintrud.gov.ru/docs/laws/130): учесть локализацию при сборе данных граждан РФ. План размещения — сервер/БД в РФ; это не означает автоматического соблюдения всех требований закона.
- [ФНС: вопросы по ККТ, предоплате и зачёту аванса](https://kkt-online.nalog.ru/faq/): кассовый сценарий должен охватывать получение предоплаты и окончательный расчёт.
- [CloudPayments, документация](https://developers.cloudpayments.ru/): подписанные уведомления используются как основание статуса, браузерный callback не подтверждает деньги.
- [CloudKassir, документация](https://developers.cloudkassir.ru/): типы чеков, Amounts.AdvancePayment, ставки НДС и ограничение идемпотентности.
- [Telegram OIDC](https://core.telegram.org/bots/telegram-login): Authorization Code + PKCE, проверка issuer/audience/exp/подписи.
- [Google Calendar Events](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert): отдельный календарь и детерминированные идентификаторы событий.

Политика, оферта и формулировка удержания не выдуманы от имени владельца. Их следует проверить с юристом по фактической модели отношений студии и мастеров. Автоматический возврат только на внутренний баланс не объявляется универсально законным способом возврата: нужны согласованный регламент и возможность обработки денежного возврата.
