# Tattoo Office

Сайт тату-студии и коворкинга для мастеров. Эстетика — корпоративный интерфейс
конца 2000-х / начала 2010-х: глянцевые панели, скруглённые окна, канцелярские
иконки, Helvetica, чёрный / белый / бежевый.

Статический сайт: **без сборки, без зависимостей, без внешних CDN**. Открывается
файлом, деплоится на Vercel как есть.

---

## Что внутри

```
index.html          каркас окна: шапка, сцена, правая колонка, подвал
css/app.css         вся визуальная система и адаптивность
js/i18n.js          все тексты, ru/en
js/data.js          КОНТЕНТ: мастера, работы, интерьер, архив, рабочие места
js/store.js         демо-хранилище: аккаунты, брони, заявки (localStorage)
js/sound.js         интерфейсные звуки, синтезируются в WebAudio
js/drift.js         «летающие» карточки мастеров
js/placeholder.js   рисованные заглушки вместо отсутствующих фото
js/pages.js         разделы сайта
js/booking.js       личные кабинеты и сетка бронирования
js/app.js           маршрутизация и обвязка окна
assets/             логотипы, паттерн фона, иконки
vercel.json         кэш-заголовки и базовая безопасность
```

## Локальный запуск

Любой статический сервер (файлом по `file://` тоже откроется, но лучше через сервер):

```bash
python3 -m http.server 8000
# http://127.0.0.1:8000
```

## Деплой на Vercel

Сборка не нужна.

```bash
npx vercel --prod
```

Или через веб-интерфейс: New Project → импорт репозитория → Framework Preset
**Other**, Build Command пустой, Output Directory — корень. `vercel.json` уже
настроен.

## Что нужно заменить своими файлами

Фотографий в репозитории нет. Пока файла нет по нужному пути, на его месте
рисуется заглушка из `js/placeholder.js`: клипартовые рожи нулевых для
портретов, кривые тату-каракули для эскизов (кинжал, череп, ласточка,
трайбл, роза, якорь), схемы комнат для интерьера. Всё рисуется на месте,
без единого запроса наружу. Положите свои файлы — заглушки исчезнут сами.

Вариант заглушки выбирается по имени файла, поэтому у конкретной карточки
он всегда один и тот же и не скачет при перерисовке.

**Логотипы и иконки — уже оригинальные:** `assets/logo.svg` (горизонтальный
логотип в шапке), `assets/mark.svg` (круглый знак в подвале),
`assets/pin-active.png` и `assets/pin.png` (канцелярские кнопки: активный и
неактивный пункт меню). Менять их не нужно.

Фоновый водяной знак собран из того же круглого лого: `assets/pattern.svg` и
`assets/pattern-dark.svg` — это плитка 200×200 с двумя знаками. Если поменяете
`mark.svg`, плитки надо пересобрать под новый контур.

**Фотографии — нужно положить свои:**

```
assets/masters/<id>.jpg          портрет мастера      (вертикальный, ~3:3.6)
assets/works/<id>-p1.jpg …       портфолио            (вертикальные, ~3:3.5)
assets/works/<id>-d1.jpg …       черновики
assets/interior/scan.jpg         3D-скан пространства
assets/interior/1.jpg … 6.jpg    фотографии интерьера
assets/auth/master.png           картинка на странице входа мастера   (16:9)
assets/auth/customer.png         картинка на странице входа клиента   (16:9)
assets/users/<почта>.jpg         аватар посетителя в кабинете
```

`<id>` — идентификатор мастера из `js/data.js` (`zinaida`, `mr-a`, `sexova`, …).

**Тексты.** Мастера, работы, архив, рабочие места и цены — `js/data.js`.
Подписи интерфейса, бегущая строка, документы — `js/i18n.js` и `DOCS` в
`js/pages.js`. Адрес, телефон и ссылка на карты — `CONTACTS` в `js/data.js`.

## Эффекты

**Летающие карточки.** Карточки мастеров плавают внутри белого окна и
отскакивают от границ, как заставка DVD. Карточки **сталкиваются между собой**
и расходятся, поэтому никогда не наезжают одна на другую. Движение хаотичное:
каждые 1–3 секунды карточка получает случайный толчок, меняющий курс и
скорость (34–58 px/сек). Карточка под курсором **замирает** — иначе в неё
невозможно попасть; то же при фокусе с клавиатуры. Если карточки физически не
помещаются в окно без нахлёста, а также на узких экранах и при включённом
системном «уменьшить движение» — раскладка переключается на обычную сетку.

Скорость и «характер» движения правятся в начале `js/drift.js`:
`SPEED_MIN`, `SPEED_MAX` и `GAP` (зазор между карточками).

**Бегущая строка** после `ABOUT:` — своя анимация, а не `<marquee>`: скорость
не зависит от длины текста, склейка бесшовная, на скрытой вкладке не крутится.

**Звук — везде.** Все звуки синтезируются в браузере, ни одного аудиофайла.
Короткие мягкие огибающие — клики офисного телефона, «печать» при
подтверждении брони, мажорный аккорд входа в систему. Озвучено всё: ссылки,
кнопки, пункты меню, вкладки, слоты бронирования, переключатели языка и темы,
выпадающие списки и выбор даты, открытие и закрытие окон, наведение курсора и
набор текста в полях. Отдельный звук для элемента задаётся атрибутом
`data-sfx="ok|error|stamp|nav|open|close|toggle|login"`, всё остальное само
получает щелчок по умолчанию.

Тумблер **♪ on/off** в шапке рядом с темой — выбор запоминается. Звук
включается после первого клика по странице: до жеста пользователя браузер
не даёт запустить аудио, поэтому контекст поднимается на первом же
`pointerdown` (плюс «пустой буфер» — этого требует iOS).

Ключ настройки звука в localStorage — `to.sound.v2`, и это намеренно. В ранней
версии звук выключался двойным кликом по переключателю темы, то есть ровно тем
жестом, которым человек включает тёмную тему и сразу возвращает светлую: звук
молча уходил в `off` и оставался выключенным навсегда. Новый ключ сбрасывает
это состояние один раз.

Громкость подобрана по замеру реального выхода: пиковая амплитуда щелчка
около 0.4 при мастер-гейне 0.95 и срезе фильтра 9 кГц. Если нужно тише или
громче — правьте `master.gain` и поле `gain` у конкретных звуков в
`js/sound.js`.

**Тема.** Светлая / тёмная, переключатель `☀ on` в шапке. Выбор темы, языка и
звука сохраняется.

## Демо-режим и что делать перед запуском

Аккаунты, брони и заявки сейчас лежат в `localStorage` браузера. Это сделано,
чтобы **весь** сайт работал сразу после деплоя — но у этого есть прямые
следствия, которые нужно понимать:

- пароли хранятся в браузере в открытом виде;
- данные у каждого посетителя свои: мастер не увидит чужую бронь с другого
  устройства, и защиты от двойного бронирования между людьми фактически нет;
- всё стирается вместе с данными сайта в браузере.

Демо-аккаунты (логин — почта): `master@tattoo.office` / `master` и
`customer@tattoo.office` / `customer` (кнопка «войти в демо-аккаунт» на
странице входа).

**Для боевого запуска** нужен бэкенд. Менять придётся только `js/store.js` —
остальной код обращается к нему через методы и о хранилище ничего не знает:

| Метод | Что должен делать на сервере |
|---|---|
| `register`, `login`, `logout` | регистрация и сессия, пароли — хэшем |
| `slotMap`, `book`, `cancelBooking` | занятость и бронь, проверка пересечений **в транзакции** |
| `myBookings`, `bookingsOn`, `stats` | выборки по пользователю и дню |
| `createAppointment`, `incomingAppointments`, `setAppointmentStatus` | заявки клиентов мастерам |
| `sendFeedback` | анонимные обращения |

Проверку двойного бронирования обязательно продублируйте на сервере: сейчас
она есть (`book()` сверяет слоты прямо перед записью), но клиентская проверка
сама по себе ничего не гарантирует.

Подойдёт любой вариант: Vercel Postgres + serverless-функции в `/api`,
Supabase, или синхронизация с внешним календарём — как было в ТЗ. Для CRM
(учёт посещений, сегментация, выгрузка) в `store.js` уже считается статистика
по мастеру: количество броней, часов и активных записей.

## Доступность и мелочи

- всё управляется с клавиатуры, у карточек и вкладок есть роли и состояния;
- уважается `prefers-reduced-motion`: движение отключается целиком;
- нет cookies, аналитики, трекеров и обращений к сторонним доменам;
- шрифт — системный Helvetica Neue с запасными вариантами, ничего не грузится.
